## 所見1（中）: Issue #73 — E2E main test#4 失敗の解析と次の一手

- 失敗テスト: `tests/e2e/main.spec.js:112`（chromium-iphone のみ）。`document.hidden` を defineProperty で偽装 → `visibilitychange` を2回 dispatch → 500ms 待ち → `mapAfter.height` と `topBarAfter.y` を ±10px で検証。
- 実装: `public/assets/map.js:257-273`。復帰時に `setTimeout(() => map.resize(), 100)`。
- 分析: `map.resize()`（Mapbox GL）は**キャンバスをコンテナ実寸に合わせ直すだけ**で、コンテナの CSS 高さや topBar の位置は変えない。テストが検証しているのは要素の boundingBox なので、失敗しているなら「resize が効いていない」ではなく「コンテナ／topBar のレイアウト自体が iphone ビューポートでずれる」可能性が高い。つまり**テストの検証対象と実装の守備範囲がずれている疑い**がある。
- 付随: テストコメントの「map.invalidateSize」は Leaflet 時代の残骸（実装は Mapbox の `map.resize()`）。修正時にコメントも更新する。
- 次の一手（Issue #73 記載どおり）: 失敗時に `#map` コンテナと canvas 実寸の両方をログ出力して実測 → (a) コンテナは正しく canvas がずれる→実装側（resize タイミング）、(b) コンテナ自体がずれる→テスト側（期待値 or 待機条件）の分岐で対処。
